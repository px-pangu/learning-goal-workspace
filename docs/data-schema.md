# 数据表字段定义

页面直接读写下面三张 WorkBuddy 资料库数据表。字段名必须完全一致（页面的读写映射按中文字段名走）。

## 1. 学习目标

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 目标名 | text | ✅ | 最多 30 字 |
| 单位 | text | ✅ | 个 / 页 / 节 …… 空值按「个」处理 |
| 总量 | number | ✅ | 必须 > 0 |
| 截止日 | date | ✅ | `YYYY-MM-DD` |
| 创建日 | date | ✅ | 连续天数不早于创建日计算 |
| 配色 | text | | `#rrggbb`，不在内置色板内时回退为 `#6366f1` |
| 障碍 | text | | 与「对策」合用拼成「如果〈障碍〉，我就〈对策〉」，最多 60 字 |
| 对策 | text | | 同上 |
| 示例 | checkbox | | 置 `true` 表示示例数据，「清空示例」只删这一类 |
| 目标ID | text | ✅ | 客户端生成的业务主键，形如 `seed-g1` / `id-m9x2k-4a1b7` |

## 2. 每日打卡记录

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 日期 | date | ✅ | `YYYY-MM-DD`，补记时为实际学习日期 |
| 目标名 | text | | 冗余字段，便于在表里直读 |
| 打卡量 | number | ✅ | 必须 > 0；同一天可多条叠加 |
| 单位 | text | | 冗余字段 |
| 分钟 | number | | 选填；未填的记录不参与 14 天柱状图的分钟堆叠（不硬凑） |
| 补记 | checkbox | | 置 `true` 时列表显示「补」标；仍按真实日期参与连续天数与推算 |
| 目标ID | text | ✅ | 关联「学习目标.目标ID」 |
| 记录ID | text | ✅ | 客户端生成的业务主键 |

## 3. 每周复盘

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 周起始日 | date | ✅ | 该周的**周一**日期，即业务主键（每周最多一条） |
| 保持 | text | | 四栏复盘之一，最多 100 字 |
| 问题 | text | | 同上 |
| 尝试 | text | | 同上 |
| 下周预案 | text | | 同上 |

## 幂等约定

页面在「本机有、云端没有」时的补写，按业务主键判重：

- 学习目标 → `目标ID`
- 每日打卡记录 → `记录ID`
- 每周复盘 → `周起始日`

所以这三列不要出现重复值，否则补写会串。页面的 SDK 调用里，`databaseId` 必须是**字面量或名为 `DATABASE_ID` 的常量**（多表页面逐个表写字面量；`DATABASE_ID_GOALS` 这类命名在静态校验中不通过）。
